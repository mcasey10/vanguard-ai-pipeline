AI Product Pipeline by Role

🧬 Design Process

A portfolio project demonstrating a structured AI-assisted PM → PD → Dev pipeline applied to a hypothetical Vanguard Sell & Rebalance tool. This document is the central point of organization for all project artifacts — each step links to the source materials, decisions, and outputs produced at that stage. Artifacts marked with a link icon are publicly accessible; others are noted as in-progress or restricted.

Problem framing + competitive research
🎯 Problem statement
Defined user problem, target segment, and the gap in Vanguard's existing portal. Parallel competitive framing run in Claude.ai, ChatGPT, and Gemini to surface differing framings and reconcile into a refined problem statement.

Screen generation
◈ Screens (Figma)
Claude Code reads from the PDB (screen inventory and PD decisions log) and references the design system library in Figma to produce native Figma frames directly in the Screens file. In practice this step revealed a key limitation: CC handles well-specified component usage reliably, but cannot navigate design-space exploration — decisions about component architecture, variant structure, and conditional nesting require human judgment. This distinction between AI execution and human design judgment is the central learning of this phase. Gate: complete screen inventory and validated design system components.

8
Interaction wiring + micro-interactions
◈ Figma ⬡ Framer ⬡ ProtoPie
Three parallel prototype tracks evaluated. A structured wiring spec was produced first — frame inventory, gap analysis, ambiguity resolutions, and a phase-ordered connection list — before any wiring was applied. Track A (Figma native) used CC + Figma MCP to apply 37 of 45 connections programmatically in a single session after consolidating all frames onto one page; 8 variant-swap interactions blocked by Figma Plugin API remote component restriction and deferred. Track B (Framer) used the native overlay system for the SaveDiscard modal with scrim, animation, and dismissible backdrop — interactions not achievable in Figma prototype mode; full happy path and branch paths wired manually. Track C (ProtoPie) confirmed strong Figma import fidelity and auto-import of existing prototype connections, but free plan's 2-scene hard limit and AI features paywall made full evaluation impractical.
T4
Claude CodeTrack A — produced a 3-prompt wiring spec (DS audit → frame inventory + gap analysis → connection spec with ambiguity resolutions), then applied 37 prototype connections in a single session via Figma MCP. Zero failures on Phases 1–3 (happy path, branches, overlays). Phase 4 variant swaps blocked by Figma Plugin API remote component restriction — requires manual UI application. Key learning: all frames must be on one page before wiring; frames moved between pages receive new node IDs. Figma MCPTrack A — wrote all prototype connections directly into the Screens file. Cross-page navigation was the initial blocker; resolved by consolidating all frames onto a single page. Frame consolidation used cut/paste (not copy) to preserve DS library references and avoid duplicate node IDs.
T2
FramerTrack B — imported all 12 screens via Figma plugin (copy-paste workflow). Built SaveDiscard modal as a native Fixed overlay with scrim, Ease In/Out animation, and click-outside dismissal. Hover-triggered kebab → delete confirmation wired as two-step interaction. Full happy path and branch paths wired manually. Shareable URL available immediately after save. Limitations: no built-in hotspot visualization (Figma's Show Hotspots has no equivalent); viewport height locked to first page dimensions unless presenting full screen; import workflow is copy-paste via plugin, not a direct Figma file import; no CC/MCP integration path. AI features (Framer AI) are oriented toward marketing site generation, not prototype wiring. Figma MakeEvaluated in prior sessions for screen generation — not used for wiring. Figma Make generates new React versions per prompt rather than writing to existing Figma frames, making it unsuitable for systematic wiring of an existing screen inventory.
T3
ProtoPieTrack C — evaluated but not completed. Strong Figma import: preserves auto-layout, constraints, component variants, and existing Figma prototype connections (auto-imported without manual wiring). Live Figma component sync maintained post-import prevents direct text editing in ProtoPie Studio. Free plan hard limits: 2 scenes per prototype (enforced in Studio, not just cloud uploads), AI features require Basic plan ($13/month). Mobile-first tool — desktop prototyping supported but secondary. Best suited for conditional logic prototypes with variables and formulas; this value did not materialize within free plan constraints.
Tool comparison — when to use each
Figma native prototype
Best for design review, stakeholder walkthroughs, and Dev handoff. CC-automatable via Figma MCP. Built-in hotspot visualization. Stays in the same file as annotated screens. All frames must be on one page — no cross-page connections.
Framer
Best for demonstrating interaction quality and animation fidelity to a technical audience. Native overlay system with scrim and animation. No page limitations. Shareable URL immediately. No AI automation; no hotspot visualization; viewport height quirks require full-screen presentation.
ProtoPie
Best for conditional logic prototypes with variables and formulas that go beyond frame-to-frame navigation. Strongest Figma import fidelity. Auto-imports existing Figma prototype connections. Free plan too limited for meaningful evaluation — Basic plan required.
